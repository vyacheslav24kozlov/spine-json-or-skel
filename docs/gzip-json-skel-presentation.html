GZIP и Spine: JSON vs SKEL

Почему gzip не превращает JSON в SKEL

GZIP уменьшает размер передачи по сети, но не убирает JSON.parse().

Что такое gzip?

GZIP — алгоритм сжатия. Во время передачи JSON становится бинарным потоком, но после загрузки браузер автоматически распаковывает его.

JSON → gzip → сеть → gunzip → JSON string

JSON + gzip

response.text()
↓
JSON.parse()
↓
JS Object Tree
↓
Spine Objects

Главный недостаток JSON остаётся: JSON.parse().

SKEL + gzip

response.arrayBuffer()
↓
Uint8Array
↓
SkeletonBinary.readSkeletonData()

Нет промежуточного дерева JS объектов.

Что решает gzip?

ПроблемаGZIP
Размер сети✅
JSON.parse❌
GC❌
CPU❌

Что происходит в твоем коде?

await response.text()

Браузер уже сделал gunzip и UTF-8 decode.

await response.arrayBuffer()

Браузер возвращает уже распакованные байты.

Размеры после gzip

ФорматБез gzipС gzip
JSON1.5 MB250 KB

JSON часто сжимается лучше из-за повторяющихся ключей.

Итог

  1. GZIP влияет только на сеть.
  2. После распаковки JSON снова текст.
  3. SKEL всё ещё требует меньше CPU.
  4. После SkeletonData runtime одинаков.
