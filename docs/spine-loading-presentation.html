Загрузка Spine-ассетов

Как loadSpineAssets и parseSkeletonData из src/shared/spineLoader.ts превращают файлы в SkeletonData

spine-json-or-skel Spine 4.2.43 @esotericsoftware/spine-core

Проект сравнивает форматы skeleton: JSON и SKEL (binary). Atlas один и тот же — текстура и регионы берутся из symbols.atlas + symbols.webp.

Файлы .atlas + .json/.skel
→
loadSpineAssets fetch + TextureAtlas
→
LoadedSpineAssets atlas + bytes/text
→
parseSkeletonData SkeletonData

Какие файлы участвуют

Файл Роль Когда загружается
symbols.atlas Текстовое описание texture atlas: имя PNG/WebP, размер страницы, координаты регионов (спрайтов) Всегда, для JSON и SKEL
symbols.webp Сама текстура. В loadSpineAssets не fetch-ится напрямую — atlas ссылается на неё; WebGL-загрузчик подтянет при рендере Playback (AssetManager)
animation.json Skeleton в JSON: bones, slots, skins, animations, events format === "json"
animation.skel Тот же skeleton в бинарном формате Spine format === "skel"
Atlas нужен обоим форматам: skeleton хранит логику и ссылки на attachments, а atlas — где на текстуре лежит каждый регион.

Этап 1: loadSpineAssets

Асинхронная загрузка через fetch. Atlas и skeleton качаются параллельно через Promise.all. 

const [atlasResponse, skeletonResponse] = await Promise.all([
  fetch("/assets/symbols.atlas"),
  fetch(format === "json"
    ? "/assets/animation.json"
    : "/assets/animation.skel"),
]);

Atlas

  1. atlasResponse.text() — строка atlas-файла
  2. new TextureAtlas(atlasText) — парсинг регионов
symbols.webp
size:2048,2048
filter:Linear,Linear
1_coin_blick
bounds:1904,1371,91,136
...

Skeleton (зависит от format)

JSON:

  • skeletonResponse.text()
  • сохраняется в skeletonText
  • skeletonBytes = пустой массив

SKEL:

  • arrayBuffer() → Uint8Array
  • skeletonText = ""

Результат loadSpineAssets

Функция возвращает объект LoadedSpineAssets:

interface LoadedSpineAssets {
  atlas: TextureAtlas;        // уже распарсенный atlas
  skeletonBytes: Uint8Array;  // для SKEL
  skeletonText: string;       // для JSON
  fileSizeBytes: number;      // для benchmark
}

Важно

  • На этом этапе skeleton ещё не распарсен — только сырые байты или текст скачаны из сети.
  • TextureAtlas уже создан: известны имена регионов и их UV/ bounds на texture page.
  • Текстура symbols.webp пока не обязательна для parse-benchmark в браузере — достаточно atlas + skeleton data.

Этап 2: parseSkeletonData

Синхронный парсинг skeleton в структуру runtime SkeletonData. Формат выбирается параметром format.

TextureAtlas из LoadedSpineAssets
→
AtlasAttachmentLoader связка attachment ↔ регион
→
SkeletonJson / SkeletonBinary readSkeletonData()
→
SkeletonData готов к использованию 
const attachmentLoader = new AtlasAttachmentLoader(assets.atlas);

if (format === "json") {
  const skeletonJson = new SkeletonJson(attachmentLoader);
  return skeletonJson.readSkeletonData(assets.skeletonText);
}

const skeletonBinary = new SkeletonBinary(attachmentLoader);
return skeletonBinary.readSkeletonData(assets.skeletonBytes);

Роль AtlasAttachmentLoader

При чтении skeleton runtime встречает attachments типа Region, Mesh и т.д. Имена вроде mini_coin, blick должны сопоставиться с регионами atlas.

Что делает loader

  • Получает имя attachment из skeleton data (JSON или binary)
  • Ищет регион в TextureAtlas по имени
  • Создаёт RegionAttachment / mesh с UV, размерами, offsets

В skeleton JSON

"coin": {
  "mini_coin": {
    "path": "minor_coin",
    "width": 171,
    "height": 171
  }
}

В atlas

minor_coin
bounds:...
offsets:...
rotate:...

Без atlas парсер не сможет построить attachments — skeleton и atlas всегда идут парой.

Что внутри SkeletonData

readSkeletonData() строит полное описание персонажа/сцены в памяти:

  • bones — иерархия костей, transform setup
  • slots — слоты отрисовки, blend modes
  • skins — набор attachments по слотам
  • animations — ключи по времени
  • events — onStartWinbox, onOpacity…
  • constraints — IK, path, physics…
  • metadata — hash, версия Spine

Пример из animation.json

{
  "skeleton": { "hash": "...", "spine": "4.2.43" },
  "bones": [ { "name": "root" }, { "name": "main", "parent": "root" }, ... ],
  "slots": [ { "name": "coin", "bone": "coin", "attachment": "mini_coin" }, ... ],
  "animations": { "idle": { ... }, "win": { ... } }
}

JSON vs SKEL на этапе парсинга

JSON SKEL
Загрузка .text() .arrayBuffer()
Парсер SkeletonJson SkeletonBinary
Размер файла ~21 KB ~9.5 KB
Atlas Одинаковый путь — AtlasAttachmentLoader
Результат Одинаковый тип — SkeletonData
Разница в производительности benchmark-а — в скорости readSkeletonData(), а не в содержимом SkeletonData после парсинга. Версия runtime должна совпадать с версией экспорта (4.2.43).

Дальше по pipeline

После SkeletonData проект создаёт runtime-инстансы:

SkeletonData шаблон
→
createRuntimeInstance Skeleton + AnimationState
→
updateRuntimeInstance update → apply → worldTransform
→
drawSkeleton WebGL render 
const skeleton = new Skeleton(skeletonData);
const animationStateData = new AnimationStateData(skeletonData);
const animationState = new AnimationState(animationStateData);
animationState.setAnimation(0, animationName, true);

Два пути загрузки в проекте

  • Parse benchmark — loadSpineAssets + parseSkeletonData (fetch)
  • Playback benchmark — AssetManager из spine-webgl (atlas + json/skel + текстуры для GPU)

Оба пути в итоге вызывают parseSkeletonData с одинаковой структурой LoadedSpineAssets.

Краткое резюме

  1. loadSpineAssets — сеть: atlas всегда + json или skel; atlas сразу парсится в TextureAtlas.
  2. LoadedSpineAssets — промежуточный контейнер: atlas готов, skeleton — сырые данные.
  3. parseSkeletonData — CPU: через AtlasAttachmentLoader skeleton превращается в SkeletonData.
  4. Формат JSON/SKEL влияет только на способ чтения skeleton; atlas и итоговая модель данных общие.
